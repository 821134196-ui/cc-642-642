# 百货礼盒拆包退货与组件复原系统

顾客退回礼盒后，柜台核对商品、配件、赠品，逐件登记完好/缺失/破损，按**售出时组合价格分摊**
计算退款；只有**全部组件完好**的礼盒才恢复整盒库存，否则只有完好散件各自入库。
两个柜台可同时为同一订单建单登记，但最终**只能产生一笔有效退款和一次库存调整**。

- 后端：Java 17 + Quarkus 3（REST）+ Hibernate ORM + SQLite（Xerial JDBC）
- 前端：Svelte 4 + Vite，构建后由 Quarkus 静态托管
- 照片：本地磁盘保存（`data/photos/`），元数据挂在原订单下
- 支付：内置模拟支付网关，退款返回回执号
- 存储：SQLite 文件 `data/giftbox.db`

## 一条命令启动

```bash
./run.sh
```

首次运行会自动构建前端、打包后端，然后启动。浏览器打开 <http://localhost:8080>。

- `./run.sh --rebuild`：强制重新构建后启动
- `./run.sh --dev`：前后端开发模式（前端 :5173 热更新，后端 :8080）

> 需要 JDK 17+、Maven、Node 18+。若当前用户无系统级 JDK/Maven，脚本会自动使用 `~/tools` 下的本地安装。

## 办理流程

1. **调出原订单**：按订单号查询，并列看到“应有组件”与“实际清点”。
2. **逐件登记**：每行填写 完好 / 破损 / 缺失，三者之和必须等于应有数量。
3. **报价与依据**：赠品缺失、商品破损分别展示扣减金额、单件参考报价与依据文字；
   页面显示“退款＋扣减＝组合价”的勾稽标记。
4. **顾客确认退款明细** → 柜台办理退款 + 入库。
5. **检查照片与主管意见**保存在退货单（原订单）下，随时回看处理过程。

## 关键规则

### 金额分摊（`PricingService`）

- 组合价以**订单成交快照**为准，而非礼盒模板现价。
- 以各组件单件参考报价为权重，用**最大余数法**把组合价精确分摊到每一个应有件，
  所以各行分摊额之和、退款＋扣减都**恒等于**售出组合价（无 1 分钱误差）。
- 完好件的分摊额退还；破损件与缺失件的分摊额作为扣减，赠品缺失与商品破损分行列示。

### 库存复原（`ReturnService.complete`）

- 所有组件完好 → 写入 1 条 `BOX`（整盒）批次。
- 存在任何破损/缺失 → 绝不写整盒，只按完好组件写 `LOOSE`（散件）批次；
  破损件、缺失件不入库。因此库存里不可能出现未真正复原的整盒。

### 并发与重复退款（订单级条件认领 + 幂等）

- 完成办理在单事务内执行条件更新：
  `UPDATE sale_order SET return_state='REFUNDED' WHERE id=? AND return_state='OPEN'`。
  更新行数为 0 即说明已被另一柜台办理，本单记为 `REJECTED`，只留拒绝审计记录，
  **不退款、不入库**。SQLite 单写者 + 连接池 1 保证仲裁原子。
- 同一退货单重复办理：幂等回显原回执，不二次退款、不增加库存。
- 旧回执重放（`/api/returns/replay-receipt/{receiptNo}`）：仅回显原成功记录。

## 主要接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/orders`、`/api/orders/by-code/{code}`、`/api/orders/{id}` | 调出订单/应有组件/退货记录 |
| POST | `/api/returns` | 新建退货检查单（可两个柜台各建一单） |
| PUT | `/api/returns/{id}/lines/{lineId}` | 逐件登记完好/破损/缺失 |
| POST | `/api/returns/{id}/photos` | 上传检查照片（原始字节，本地保存） |
| POST | `/api/returns/{id}/supervisor-notes` | 主管意见 |
| POST | `/api/returns/{id}/confirm` | 顾客确认退款明细 |
| POST | `/api/returns/{id}/complete` | 办理退款 + 入库（并发安全、幂等） |
| POST | `/api/returns/replay-receipt/{receiptNo}` | 旧回执重放（仅回显） |
| GET | `/api/stock` | 整盒/散件库存核对 |

- `ReturnFlowTest`（端到端 HTTP）：
  破损+缺失只散件入库且金额勾稽；全完好恢复整盒；

  重复办理与旧回执重放均不二次退款、不增加库存。
